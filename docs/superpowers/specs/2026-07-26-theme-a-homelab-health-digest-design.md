# Theme A — Homelab health digest and the Home Assistant bridge

**Date:** 2026-07-26
**Status:** Approved design, pending implementation plan
**Scope:** First of three integration themes. B (knowledge capture) and C (infra
consolidation) get their own specs later.

## Goal

Give the homelab a feedback loop it currently lacks, and connect Home Assistant to the
services it cannot reach on its own — without introducing any credential that has to be
created by hand.

## Why this shape — the finding that drove it

Every failure found while auditing this homelab was **chronic, not acute**:

| Defect | How long it was broken |
|---|---|
| `speedtest-exporter` crash-looping (8,030 restarts, OOMKilled) | months |
| `promtail` unready — no Pi pod logs reaching Loki | weeks |
| Grafana crash-looping (305 restarts, duplicate default datasource) | weeks |
| Mac Mini disk filling (24 GB free, −41 GB in a week) | days |
| `whisper.<domain>` routed to MinIO; open-webui STT never worked | months |

Nothing died suddenly at 3am. Things rotted silently while a fully working Prometheus
watched and told nobody. **The gap is regular visibility, not interruption.**

This rules out the conventional answer. Paging infrastructure (SMTP, push, escalation
policies) optimises for acute failure, costs a hand-made credential, and would not have
caught any of the five defects above sooner than a daily check would.

It also collapses the design: "alerting" and the "daily home conditions digest" become
**one workflow**, not two systems.

## Architecture

### Hub roles

The audit surfaced a category error worth recording: open-webui was being treated as an
integration point. It is a chat UI — no triggers, no scheduler, no webhooks — so every
integration through it requires a human typing. Three hubs, three jobs:

| Hub | Role |
|---|---|
| **n8n** | Unattended orchestration — cron, webhooks, service-to-service. **The integration hub.** |
| **open-webui** | Interactive AI — human in the loop, chat, voice, RAG. A *consumer* of AI, not an orchestrator. |
| **Claude Code + MCP gateway** | Reasoning-heavy work. Existing scheduled routines already cover this well. |

The Whisper defect was a symptom of the confusion: open-webui was wired to reach Whisper
over the public internet — out through Cloudflare, through Access, and back — when both
containers run on the same machine.

### Credential policy

Credentials that prove identity to a **third party** (Apple, Grafana, Home Assistant)
cannot be self-issued — that is their purpose. Credentials that are **shared secrets
between services we own** (a webhook ID) can be generated by Terraform.

This design uses only the latter, plus keys that already exist. **No new manual
credential is required.**

| Need | Avoided by |
|---|---|
| Read home sensor data | Querying Prometheus — Home Assistant metrics are already scraped |
| HA events → n8n | HA pushes to an n8n webhook; no token on either side |
| n8n → Whisper / Ollama | No auth on either service |
| n8n → Obsidian | `obsidian_api_key` already exists in tfvars |

Confirmed present in Prometheus: `homeassistant_sensor_humidity_percent`,
`_temperature_celsius`, `_battery_percent`, `_illuminance_lx`, `_pressure_hpa`,
`_state`, `_timestamp_seconds`.

### Endpoints

All internal. Nothing on this path traverses Cloudflare — that is what broke both the n8n
API and Whisper.

| Target | Address |
|---|---|
| Prometheus | `http://192.168.0.128:30090/api/v1/query` |
| Whisper | `http://host.docker.internal:9090/v1` |
| Ollama | `http://host.docker.internal:11434` |
| Obsidian Local REST API | `https://host.docker.internal:27124` + existing `obsidian_api_key` |

The Obsidian endpoint serves HTTPS with a self-signed certificate, so the n8n HTTP node
must be set to skip TLS verification for that host — expected, not a workaround. It also
means the digest depends on Obsidian running on the Mac; if it is closed, the workflow
should fail loudly rather than silently skip the write.

## Component 1 — Health digest (build first)

A single scheduled n8n workflow, replacing the alerting system that would otherwise be
built:

```
n8n (daily cron)
  → Prometheus: up == 0, container restart deltas, filesystem %, blackbox probe state
  → Prometheus: homeassistant_sensor_* (temperature, humidity, battery)
  → Ollama: summarise anomalies in plain language
  → Obsidian: append a "Homelab health" section to today's daily note
```

It lands in the same daily note as the existing `rss-daily-digest` routine, so it will
actually be read — the property that matters most.

### Conditions reported

Chosen to match the failure history, deliberately few. A digest nobody reads is the
problem being solved; a noisy one recreates it.

| Condition | Expression |
|---|---|
| Service down | `up == 0` for 5m |
| Pod crash-looping | restart count increasing over 15m |
| Disk filling | filesystem usage > 85% |
| Endpoint probe failing | blackbox probe down 5m |

These are also defined as `PrometheusRule` CRDs from the `prometheus-stack` module, so
they appear in Grafana and are queryable by n8n. **No Alertmanager receiver is
configured** — delivery is the digest's job.

### Accepted limitation

A sudden outage waits until the next digest. Given the failure history this is an
acceptable trade. If a genuinely urgent class of failure ever appears, push notification
can be added for that rule alone without touching this design.

## Component 2 — Home Assistant → n8n bridge

Direction matters: **HA pushes, n8n does not pull.** An HA automation calls an n8n webhook
via `rest_command`. This needs no long-lived token, and it keeps HA's own automation
engine authoritative for anything internal to HA.

Automations that live entirely within Home Assistant — curtains on a schedule, lights on
motion, humidity triggering a fan — **stay in Home Assistant**. They are faster and more
reliable there. n8n is only for reaching what HA cannot: local AI, Obsidian, MinIO.

## Component 3 — Voice memo → Whisper → Obsidian

Audio is dropped into a watched folder; n8n transcribes it and files the result as a note.

- **Folder:** `/Volumes/Samsung T7 Touch/homelab-data/voice-inbox`, mounted into the n8n
  pod using the same hostPath pattern as the existing `n8n-data` volume (proven working).
  The iCloud Obsidian vault path is deliberately avoided — iCloud files may be
  non-materialised placeholders, and `~/Library/Mobile Documents` is not reliably shared
  with Docker Desktop.
- **Detection: polling, not filesystem events.** inotify does not reliably cross the
  Docker Desktop VM boundary on macOS; a Local File Trigger would look correct and
  silently never fire. A schedule trigger (~2 min) lists the folder instead.
- **Idempotency: move processed files to `processed/`.** No state to track, no double
  transcription, and it is self-evident which files were handled.

**Known trade-off:** the T7 folder is reliable but adds capture friction — files must be
dropped there rather than just recorded. If that friction kills the habit, an iOS Shortcut
posting to an n8n webhook is the lower-friction alternative and swaps in without changing
the rest of the workflow.

## Component 4 — Bambii care routine

Reminders and activity logging. The music trigger itself **stays in Home Assistant**,
where `bambii_music_on` already lives; n8n adds only logging and reminders.

## Component 5 — AI-assisted home queries

Natural-language questions ("was it humid last night?") answered by translating to a
Prometheus query, running it, and phrasing the result with Ollama. Highest effort, built
last, reusing the query plumbing proven by Component 1.

## Build order

1. **Health digest** — exercises the whole chain (Prometheus → Ollama → Obsidian) with the
   least complexity, so it de-risks everything after it
2. **HA → n8n bridge** — small, unblocks event-driven work
3. **Voice memo** — the workflow that most needs n8n
4. **Bambii routine** — small once the bridge exists
5. **AI queries** — last, on proven plumbing

Each is independently shippable. Stopping after step 1 still closes the visibility gap.

## Verification

Prove the **output**, never a node's success status. Health checks lied repeatedly during
the audit — `n8n_health_check` reported `ok` while every authenticated call failed, and
Grafana's Loki datasource showed red while queries worked.

1. Health digest: a "Homelab health" section appears in today's Obsidian note with values
   that match a manual Prometheus query.
2. Digest catches real faults: stop a non-critical container, confirm the next run reports
   it.
3. HA bridge: an HA automation fires and the n8n execution log shows the payload.
4. Voice memo: drop an audio file; a note appears with correct transcribed text and the
   file moves to `processed/`.
5. No new credential was created by hand at any point.

## Out of scope

- **Email / SMTP alerting** — needs a hand-made Apple app-specific password and optimises
  for a failure mode this homelab does not have.
- **Alertmanager receivers** — rules are defined; delivery belongs to the digest.
- **Migrating existing HA automations to n8n** — strictly worse than native HA.
- **Rebuilding RSS or vault ingest in n8n** — the existing `rss-daily-digest` and
  `wiki-nightly-ingest` Claude routines do this with reasoning n8n cannot match.
- **Themes B and C** — separate specs.
